# One owned compose workflow and authenticated candidate publication

Goal12–17 and the owned-admission plan apply. Finish admission review/evidence
first. This records the next integrated runtime unit before implementation;
neither the plan nor admission storage controls prove a native query is ready.

Reuse the actual pinned compose_round vendor/closed parser, OperationExecution,
OperationTasks and RoleWorkflow product readers. Upstream recursion._run_stage
owns benchmark filesystem/retries/accounting; adapting the existing Javis owner
avoids a second executor. No new account/model/ledger or whole repository refactor.

1. Concrete ComposerService(RoleWorkflow), product kind compose only. Begin with
   actual owner/authorization/original experiment generation and closed event
   request. Current consent/input/source/domain guards precede native verification;
   verification remains bound to those same current guards. A false capability
   or unsupported host-profile format must not create an operation/call. Creation
   uses actual Records and immutable events in one transaction, then authenticates
   the exact own mutation through current(operation=...). No public input rebuild
   inside callbacks. The schema enforces one compose across event keys.
2. Use _run_owned and the actual shared tasks start/join/cancel/drain/recovery
   lifecycle. Cold completed replay returns the stored outcome; interrupted start
   is historical metadata, never implicit permission to run again. Preserve
   infrastructure retry bounds; no structural repair or semantic resampling gives
   another compose. Invalid output/incomplete native result publishes no candidate.
3. Publication reads the actual completed product through RoleWorkflow._product,
   preserving exact required product/native checks, call/status/attempt/config/
   engine_at/trace/decision/report/artifact identity. Reparse the authenticated raw
   artifact with the current saved compose projection. Model decisions remain
   unreviewed claims. A keep_base outcome is valid and grants no activation.
4. Reuse existing SkillCandidates validation, redaction, encrypted content/patch/
   provenance, evidence resolution and cold records. Ordinary/manual/generated
   staging must remain capped at two. Only the typed publication bound to the
   actual compose result/consent may produce ordinal3, with authority_id NULL,
   semantic unreviewed and dependency unresolved. Do not let _region auto-inherit
   an editable-region grant. Any factored insertion primitive must be private and
   all positive typed links must remain mandatory, not a caller limit/override.
5. Persist one immutable composition, encrypted decisions and the new candidate
   atomically; deferred FK permits composition-before-candidate. output_hash is
   the existing result REPORT blob, not raw model output. Verify report/artifact
   independently. Provenance/read_proposal must authenticate composition, exact
   original two candidates/inputs/basis, current scope and raw patch. Do not mint
   an ordinary owner request as if the model itself approved an edit.
6. All slow blob/source/policy/product observations precede the final current
   source guards and SQL-only CAS. Test grant/off/source/history/domain drift at
   the final boundary, rollback/no candidate leak, keep_base and invalid output,
   actual tasks lifecycle with declared fixture seams, event replay/conflict,
   one-compose and cold metadata. Synthetic fixtures are storage/control evidence
   only; never fabricate successful native ACKs or actual account qualification.
