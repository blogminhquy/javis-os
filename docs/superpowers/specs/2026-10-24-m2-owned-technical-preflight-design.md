## Decision and honest endpoint

Implement a **Session-owned preflight vertical**: `QualificationSession.verify_native()` → `NativeParentBoundary.verify_qualification()` → existing Guardian/bootstrap → authenticated startup3 → existing native worker → existing SDK capture factory → existing durable image decisions → actual drain → a typed technical preflight result with `account_ready=False` and `supported=False`.

This consumes candidate authority at an actual native owner before acquisition. It proves the two guarded fixed observations and startup/environment ownership; it does not execute a query. Only `kind='preflight'` is enabled for startup3. Trial/operation startup3 consumers continue to refuse even though their pure parser already understands the data. No attempt binding, query budget debit, engine ACK, trial/operation capability, product publication, or release registration is inferred from preflight.

Why this slice: attempt execution would additionally need current baseline5/view4/operation2 admission, durable attempt binding, technical capability, accounting ACK, and a typed publisher/cold reader. Those form the next separate query unit. A permit-only or parser-only unit would not close a native integration boundary. Implementing the entire query/publisher pipeline now would obscure the smaller ownership defect.

Split off a small independently reviewable prerequisite **P0: categorical product refusal**. **P1: the preflight vertical** is one cohesive implementation/review unit; do not split it into unused helper commits presented as completed integration.

### Concrete authority and lifetime

1. `verify_native()` is single-use per Session; reserve that flag before an await. Preflight consumes zero model queries and cannot be replayed to mint capabilities. Future query runs use existing bind_attempt/maximum_queries; this unit does not redefine that budget.
2. `_assert_native_current` verifies exact Session type/open/unexpired state, same assets/principal/root/run anchor, authenticated `read_run` equality, and exact current candidate registry key/value. At launch, re-observe `_runtime_identity` and `observe_release` and compare fingerprint, content and manifests to the saved Session snapshot; mismatch fails before Guardian acquisition. Fixed source guards then protect declared files through native lifetime. Revalidate live Session/review and static runtime identity for each durable image decision; keep the final recheck provided by NativeImageDecisionStore.persist. There is no caller-supplied `current=True` seam.
3. Allocate private preflight scratch beneath Session.root; use `Session.environment(scratch)` to create a unique empty HOME. Recheck HOME existence, ordinary ancestry, emptiness and exact path/envelope relationships immediately before start. Do not require HOME to stay empty after CLI executes: its own writes are allowed only within owned storage.
4. Construct GuardianSessionV2 with the two existing invocations, per-run nonce, real manifests and closed persistence callback. **Current constructor only validates/copies Python data; it does not acquire files, handles, sockets or processes.** Set native lifetime to min(60 seconds, remaining Session lifetime), refusing a nonpositive remainder. Attach the fully initialized Guardian to Session immediately before `start_qualification`, with no await/acquisition between. The caller's try/finally begins before attach/start. A constructor exception has no native acquisition to retain. A regression test pins this pure-constructor contract. No uninitialized `__new__` object is attached.
5. Parent retains the concrete Guardian, scratch path and pending/received packets. The Session's owner map keeps that parent alive. Owner states are `ATTACHED → STARTING → ACTIVE → CLOSING → DRAINED → DETACHED`; exceptions/cancellation go to CLOSING or `RETAINED_UNKNOWN`, never directly DETACHED. start_qualification consumes the one attached boundary/seed once, before `_host_windows`, `_prepare_guards`, `_pair` or Popen.
6. `Session.close()` closes launch authority immediately and preserves its existing detached tempfile finalizer. For started attached owners it requests stop on the owning event loop; an attached but unstarted owner is simply revoked and its start check refuses. Do not call `_stop` before its loop/events exist. This does not claim synchronous drain. `_send_command` checks Session closed/deadline/review after any pending durable append, inside its control lock before initiating image-authorize send. A send already initiated before revocation is in flight and must be drained; it is not retroactively called unlaunched. `cleanup()` refuses while any owner remains. `aclose_native()` retries the existing retained owners' close, never reopens a PID or relaunches.
7. Always collect/persist received and closing observations, including on cancelled/failed startup. Detach only after exact Guardian `closed is True` (its existing contract covers native drain when admitted, actual exits, task/channel/socket/handle/file closure) and durable evidence retention has settled. Before admission, the existing no-worker-acquired close path is sufficient; do not demand a nonexistent drain packet. Retain on ambiguous acquisition, failed close or evidence persistence failure. A closed Guardian with pending evidence stays attached until evidence retry completes. Successful result additionally requires the Session still current/open/unexpired, worker and guardian exit codes exactly zero and both image decisions durably allowed. Closing/evidence retry remains legal after Session expiry; it cannot restore launch authority.
8. Startup3's full qualification object remains in the authenticated stdin seed and worker packet. `worker_binding3` reuses private2 incarnation/nonces but does not erase the enclosing run/environment binding. Worker construction is data validation, not peer authentication; actual provenance is the host-held original handles, fixed bootstrap and privately shared endpoints. Arbitrary packet hashes or directly invoking a worker helper in a test never prove that provenance.
9. Worker uses `_runtime_identity` only for fresh static metadata/policy checks; no production admit_preflight/profile-registration/auth verifier is called on the technical branch. It runs actual NativeInvocationSet.preflight, validates the returned technical observations, and sends the existing preflight_complete body. Parent repeats validation against its own held Session after actual close. An unknown auth label remains diagnostic; no inference of a real account follows. Subscription contamination fails. Do not add a guessed whitelist of CLI API-key spellings to make fixtures pass.

### Closed returned object

`QualificationPreflight` is an immutable concrete host result, constructed only by the completed parent path, containing exactly:

`version=1, domain='qualification', supported=False, account_ready=False, technical_ready=True, run_hash, pin_hash, release_fingerprint, review_hash, launch_nonce, environment_hash, observation_hash, trace_hash, decision_hashes=(version_decision_hash, auth_decision_hash), cleanup='proven'`.

It has **no capability_hash** and is not an ordinary adapter result. Hash fields are lowercase SHA256; decision hashes are ordered by the two fixed invocations. Failures raise/retain rather than return technical_ready=True with unknown cleanup. Reuse the existing encrypted preflight trace event scoped by `hash({version:1, domain:'qualification', run_hash, phase:'preflight'})`; this is trace evidence, not the future typed query report. For this qualification branch only, include trace_hash in the existing `_save_preflight` event key: retries may append a new immutable trace snapshot after partial drain; they must not try to overwrite the same nonce key with changed packets. Keep the ordinary preflight key unchanged. Preserve/deduplicate accumulated packets by their existing sequence and select the final complete snapshot in the returned result. No new DB/schema/ledger. Existing qualification product/result/cold-link fences stay intact.

## No-real-account, footprint and final gates

Default tests use inert native children/fixed-output captures and real disposable DB/kernel ownership; existing no-real judge/review/team flags remain set. Do not invoke ambient CLI/SDK clients, read/copy login stores, use auth overrides, set live HOME, select another model, or send provider requests. The explicit selected-CLI gate uses only `--version` and `auth status --json` under Session-created HOME, exact literal dummy key/numeric localhost endpoint and the existing closed worker environment. No inference/query is permitted. If the installed CLI performs account/network work or needs a real login even in that confined preflight, stop and report the exact blocker rather than adapting auth output.

Candidate bootstrap conflict is real but resolvable without weakening a gate: modified source cannot use old candidate/profile fingerprints; REVIEWED_QUALIFICATION_CANDIDATES is currently empty. First finish/review/freeze this unit and observe the **installed full closure**, then independently record its exact candidate review hash in that existing authority module. The authority module is intentionally excluded from the release fingerprint, so this insertion does not create a hash cycle. It grants only the bounded technical preflight. Never auto-register computed hashes, reuse old99 or historical83 proof, fill REVIEWED_RELEASES, or ask production qualification to bootstrap its own test. Further source changes require a new reviewed candidate entry and invalidate that run's live authority.

PROFILE_SOURCES is a seed list, not the transitive closure. These existing-file edits change its hash; changed native_parent/worker/SDK/qualification_protocol and newly reached imports must also appear in observe_release inventory/manifests. No seed additions are needed merely to rename the count; test the actual closure includes every changed consumer. Reuse source-qualified environment/session/records/startup3/bootstrap/Guardian/capture/SDK/private-channel component proofs from qualification-gap.md; run focused regression checks only for affected boundaries, then root's required final exact-head CI and whole-branch review. Linux validates portable grammar/DB/exclusion only; real Windows kernel cases and selected CLI gate remain separate evidence.
