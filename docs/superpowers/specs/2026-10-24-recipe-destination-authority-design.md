## Approaches and controller choice

1. Reuse old current-authoring checks unchanged: small patch, but every applied
   canonical revision makes its own procedure unusable. Rejected.
2. Normalize away selected old capture fields: requires a growing exception list
   for target files, catalog, directory identities and settings; risks accepting
   source changes accidentally. Rejected.
3. Reobserve the concrete current source surface and original fixtures, while
   separately authenticating historical evidence and current destination consent.
   Chosen by the controller. Adds a narrowly scoped procedure-source observer
   and actual permission/selection services; leaves execution revalidate exact.

Old incidental discovery/session values are historical evidence, not facts for
the new task. The new source observer does not require those values forever to
equal the old snapshot. It does require a complete actual current capture,
unchanged protected source records and their native authority, the original
engine/language, current readable live source targets and original current-version
fixtures. Every observation is stable across its own slow reads and final CAS.
This is a new recipe-guidance contract; it grants no execution of an old view.

## Destination permission and selection APIs

RecipePermissions(plans:ExperimentPlans) exposes:

- preview(principal,experiment_id,recipe_ids,*,expected_generation,
  expected_context_generation)->dict:1..50 distinct valid ids. Filter source
  metadata without body reads; authenticate actual current destination through
  existing plan/authoring/source owners; return closed body-free pins plus
  preview_hash, decision label and authority_status=not_checked. No grant/write.
- authorize(principal,experiment_id,recipe_ids,*,expected_generation,
  expected_context_generation,expected_preview_hash,decision,event_key)->dict:
  decision must equal owner_unverified_transfer. Rebuild preview, verify exact
  hash, write encrypted basis, final current-source/SQL fences, then atomically
  authorize all exact entries. Same-event replay is cold historical metadata;
  changed payload conflicts and replay never renews authority.
- current(principal,authorization_id)->dict: authenticate original event and
  encrypted basis and current exact destination generations/policy/target/source.
  Classify every exact pinned source using current recipe/context generations,
  state, expiry and compatibility metadata: eligible entries plus body-free
  unavailable ids/reasons. Corrupt immutable pins/history refuse the whole read.
  This does not execute a model or authorize a candidate/view/apply.
- revoke(principal,authorization_id,*,expected_generation,event_key)->dict and
  get/list via from_existing(assets) remain cold, same-brain, mode-off safe and
  do not decrypt, initialize a host, migrate or probe native state.

Preview/authorize refuse any requested foreign, missing, expired, revoked,
superseded, erased or source-revoked entry before source/recipe bodies. After
authorization, current/retrieval filter those newly unavailable entries; they do
not invalidate healthy consented entries. Engine and language must match destination;
semantic owner rules must match. Target kind remains skill. The exact explicit
source→destination decision permits a different experiment/target/scope with an
unverified-transfer label; it cannot override owner rules or broaden brain,
engine/language permission. Source applicability/exclusions remain guidance.
