# Ordinary task skill snapshots (engineering scope)

The ordinary final Dashboard API branch can pin its named skill loads to one
actual running host turn. The host opt-in is the exact boolean
`context_runtime.task_skill_snapshot.enabled: true`. Absent, false or malformed
policy preserves ordinary behavior and creates no snapshot/M0 store. This code
does not change persisted settings or enable a live brain. The actual Observe
Runtime must already have a running task/step; a trace dictionary is insufficient.

The private owner receives the original host turn token and runtime objects.
Inventory discovery reads bounded descriptor-checked headers, preserves language
projections and loads no complete skill bodies. The first lazy/named hub skill
read stores exact source bytes in existing encrypted M0 blobs/events. Subsequent
reads in that task use the same bytes/hash; a new task sees a new baseline.
Metadata, selected context and hub cache stay private to the scope. They never
replace the global skill registry or publish task descriptors through shadow
refresh. Connector invalidation also invalidates private hub cache generations.

Each read checks live owner/runtime rows, source path/header/permissions and
disabled precedence. A body-only edit after pinning preserves that task's first
bytes. Protected/header/path/permission/disabled changes refuse the load instead
of silently selecting mutable files or an old mirror. Missing encrypted history
also refuses. Closing/Stop/error invalidates copied contexts; capture threads
settle before cancellation propagates, including capture failure after Stop.
The hub rechecks after asynchronous work before returning private content.

`skill_usage.bump` remains positive evidence of a completed authorized source
read. If revocation occurs while that sidecar write is settling, the read may
already be counted while delivery is refused. It does not prove delivery to a
provider, provider acceptance, model comprehension or downstream asset use.

Scope is deliberately limited to lazy selection, prompt skill metadata and the
in-process `javis_use_skill` handler in the final Dashboard API branch. It is not
a complete effective view or a sandbox for arbitrary file/helper reads. Native,
HTTP, resume, OAuth/subscription, workflow/voice/bot paths, candidates/activation
and scoped helper materialization require their separate remaining integration
and qualification. Existing earlier fast paths remain outside this opt-in branch.
This unit supplies no quality, business pilot, account or rollout evidence.

Cold `TaskSkillScope.read_receipt` authenticates immutable historical provenance
without restoring a live owner or granting permission. Existing encrypted history
is retained when a turn ends; no new schema/ledger/executor or fake revision is
introduced. Published source/runtime qualifications must match the changed source
closure; historical mismatches cannot qualify these consumers. Exact-final-head
full CI and scoped independent review remain integration requirements.
